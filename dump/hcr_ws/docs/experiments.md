# Experiments: stress-testing LIO and SLAM back-ends

Pipeline: **record once, replay into every method, score against ground truth.**

```
record_route.sh  ──►  bags/<world>_<tag>/           (dataset: /points /imu /ground_truth /odom /tf /clock)
run_method.sh    ──►  results/<world>_<tag>/<method>/  (traj bag, method.log, metrics.json, traj_xy.png)
                 ──►  results/summary.csv            (one row per dataset × method)
```

```bash
source install/setup.bash
ros2 run p3at_sim record_route.sh office base                 # ~0.4x real time on CPU rendering
ros2 run p3at_sim run_method.sh bags/office_base wheel_odom
ros2 run p3at_sim run_method.sh bags/office_base kiss_icp
column -s, -t results/summary.csv
```

## Worlds (all indoor, all with hiding spots)
| World | LIO weakness it targets | Hiding spots |
|---|---|---|
| `office` | multi-room loop round a central core: loop closure / PGO, doorway transitions | under meeting/desks tables, closets, L-partitions |
| `warehouse` | repetitive shelving aisles (perceptual aliasing for loop closure), dense occlusion | aisle ends, inside crate clusters, under workbench |
| `corridor` | 50 m featureless corridor: degenerate along x, expect drift along the corridor | side alcoves, two side rooms |
| `hall` | 40×28 m sports hall: sparse, distant returns | under the stage, mat stacks, equipment store |
| `split_level` | ramps to a mezzanine, speed bumps: z drift, pitch/roll | under the mezzanine, closet, L-partition |

Worlds are generated by `src/p3at_sim/scripts/gen_worlds.py` (furniture helpers `table`, `closet`,
`l_partition`, `shelf`). Edit the generator, re-run it, rebuild. Routes live in `config/routes.yaml`.

## Stress knobs
Set at record time (launch args of `sim.launch.py`, passed through `record_route.sh`):

| Knob | Default | Stress it applies |
|---|---|---|
| `lidar_rings` / `lidar_samples` | 16 / 1024 | sparser clouds (try 8/512), or denser (32/2048) |
| `lidar_range` | 100 | short range (e.g. 10) starves the hall world |
| `lidar_noise` | 0.01 m | range noise |
| `lidar_hz` | 10 | sweep period, so de-skew magnitude |
| `imu_hz` / `imu_noise_scale` | 200 / 1.0 | IMU rate; scales all IMU noise and bias terms |
| `distort` | true | emulate rolling-sweep motion distortion (false = instantaneous scans) |

Route-driver params after `--`: `max_v` (0.5 m/s), `max_w` (0.8 rad/s), `wobble` (sinusoidal yaw-rate
excitation, rad/s), `laps`.

```bash
ros2 run p3at_sim record_route.sh corridor sparse lidar_rings:=8 lidar_samples:=512
ros2 run p3at_sim record_route.sh office aggressive -- -p max_v:=1.0 -p max_w:=1.5 -p wobble:=0.6
ros2 run p3at_sim record_route.sh hall shortrange lidar_range:=12
```
Use a tag per condition. Every method then sees the identical data for that condition.

## Metrics (`evaluate.py`, built on evo)
- `drift_pct`: final position error / path length, start-aligned. The headline odometry number.
- `ape_rmse`: absolute error after SE(3) alignment (global consistency; this is what PGO should cut).
- `rpe_t_rmse`, `rpe_r_rmse`: error per 1 m segment (local accuracy, should be roughly back-end independent).
- `z_rmse`: vertical error (meaningful in `split_level`).

For a front-end vs front-end+back-end comparison, compare `ape_rmse` (should drop with loop
closure) while `rpe_*` stays similar.

## Maps, figures and re-timing (`build_map.py`, `retime_bag.py`)
```bash
# Bags record wall-clock receive time. A slow sim or a sleeping laptop leaves long gaps that
# `ros2 bag play` replays in full. Re-time onto /clock first (writes bag format 8, Humble reads it):
ros2 run p3at_sim retime_bag.py bags/office_loop_walltime bags/office_loop
# Maps from each pose source (scans de-skewed with per-point time; estimates aligned at the start only):
ros2 run p3at_sim build_map.py bags/office_loop \
  --method wheel_odom bags/office_loop /odom \
  --method kiss_icp results/office_loop/kiss_icp/traj /kiss/odometry \
  --out results/office_loop/maps [--export-scans bags/office_loop/scans]
```
Output: `map_<source>.ply` (open in CloudCompare/MeshLab), `maps.png`, `trajectories.png`, `errors.png`, `map_3d.png`.
`--export-scans` writes each raw scan as PLY (sensor frame, with ring/time) plus `poses_gt.tum` (about 0.37 MB per scan).

### First result: `office_loop` (31 m, 135 s sim, 1266 scans), 2026-10-28
| method | APE RMSE [m] | RPE 1 m [m] | end drift |
|---|---|---|---|
| wheel_odom | 4.56 | 0.93 | 38.7 % |
| kiss_icp (stock, 1 m voxels) | 0.049 | 0.056 | 0.08 % |
| kiss_icp_indoor (0.3 m voxels) | 0.045 | 0.032 | 0.33 % |

- The sim's wheel odometry is **wrong, not just drifting**. Heading error jumps to ~145 deg in the first 0.5 m and
  swings 0-180 deg. DiffDrive with 4 joints under skid-steer slip mis-integrates rotation. Fix the model before using
  `/odom` as a prior (e.g. calibrate an effective wheel separation, or compute odometry from ground-truth wheel speeds).
- A single short loop cannot separate the two KISS-ICP configs. Both are ~5 cm APE. Needs longer and harder routes.

## Adding a method
Add an entry to `config/methods.yaml`: a launch command that reads `/points` (and `/imu`) with
`use_sim_time:=true`, and the `nav_msgs/Odometry` topic carrying its estimate of `base_footprint`.
Input contract:
- `/points`: `sensor_msgs/PointCloud2`, frame `lidar_link`, fields `x y z intensity` (f32),
  `ring` (u16), `time` (f32, seconds from `header.stamp`; stamp = sweep start). Velodyne-style,
  so `lidar_type: velodyne` / `sensor: velodyne` presets apply. 16 rings, ±15°.
- `/imu`: `sensor_msgs/Imu`, frame `imu_link`, 200 Hz, specific force (≈ +9.8 m/s² on z at rest).
- Extrinsics from `/tf_static`: `base_footprint → lidar_link` = (0.05, 0, 0.286),
  `base_footprint → imu_link` = (−0.05, 0, 0.211), no rotation. Lidar to IMU = (−0.1, 0, −0.075).

## Simulation caveats (state these in any write-up)
- Lidar motion distortion is **emulated** from ground truth (`cloud_fields.py`), not rendered. It is
  a rigid re-projection per azimuth bin (64 bins). It does not model occlusion changes within a sweep.
- Gazebo IMU noise is white noise plus a random constant bias per run, not a random walk.
- `/odom` (DiffDrive) is ideal wheel odometry: almost no slip. It is an optimistic baseline.
- CPU (llvmpipe) rendering is needed on this WSL machine, so the sim runs at ~0.4x real time.
  Bags are in sim time, so replay at any rate is fine.
