# SLAM workspace

This is a ROS 2 workspace for the Pioneer 3-AT:

- `src/p2os2/` contains the P2OS driver, messages, and robot packages.
- `src/p3at_real/` contains the robot bring-up and SLAM launch files, configs, and teleop scripts.
- `src/kiss-icp/` and `src/unilidar_sdk2/` contain the lidar/odometry packages.
- `build/`, `install/`, and `log/` are generated by colcon and are ignored by Git.
- `cmake/CMakeLists.txt` provides CMake targets to build the workspace and start SLAM.

## Build and start SLAM

Run these commands on the ROS 2 Jazzy Linux/Jetson machine, from the repository root.
Keep the ROS environment sourced in the terminal:

```bash
source /opt/ros/jazzy/setup.bash
cmake -S slam/cmake -B slam/cmake-build -DSLAM_ROS_DISTRO=jazzy
cmake --build slam/cmake-build --target run_slam
```

`run_slam` builds the ROS workspace with colcon and then starts the existing
`p3at_real/run_slam.sh` wrapper. It creates a per-run output directory and log,
then launches the robot, lidar, odometry, SLAM, and UDP teleop receiver. The
legacy ROS 1 `unitree_lidar_ros` package is excluded from the build; the ROS 2
package is used instead.

The robot driver enables the motors during startup. Keep the robot in a safe,
clear area and have access to its physical stop before starting.

## Drive from a Windows/Linux laptop

With SLAM running on the robot, open another terminal on the laptop and run:

```bash
python slam/src/p3at_real/scripts/remote_teleop.py <JETSON_IP>
```

Focus the teleop window to drive: **W/S** forward/back, **A/D** turn,
**Space** stop, and **Esc** quit. The sender needs no ROS installation; it uses
Python's standard library and Tk. The robot and laptop must be able to reach
each other over the network (UDP port `9870` by default).

Press `Ctrl-C` in the SLAM terminal to stop the launch.
