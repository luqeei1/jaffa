# SLAM workspace

This is a ROS 2 (Humble, Ubuntu 22.04 on the Jetson) workspace for the Pioneer 3-AT:

- `src/p3at_real/` contains the robot bring-up and SLAM launch files, configs, and teleop scripts.
- `src/p2os2/`, `src/kiss-icp/` and `src/unilidar_sdk2/` are git submodules (P2OS driver, KISS-ICP
  lidar odometry, Unitree L2 driver), pinned to the versions tested on the robot.
- `src/p3at_real/patches/` + `scripts/apply_patches.sh` hold our local changes to those submodules
  (p2os2 cmd_vel keep-alive, L2 start-up reset). The `build_slam` target applies them for you.
- `build/`, `install/`, and `log/` are generated by colcon and are ignored by Git.
- `cmake/CMakeLists.txt` provides CMake targets to fetch, patch, build the workspace and start SLAM.

System packages (apt, already on the Jetson): `ros-humble-rtabmap-ros`, `ros-humble-rko-lio`,
`ros-humble-nav2-map-server`, `ros-humble-sophus`, `ros-humble-pcl-ros`, `libtbb-dev`, `robin-map-dev`,
`python3-tk`, `python3-matplotlib`.

## Build

From the repository root on the Jetson:

```bash
git submodule update --init          # first time / after a fresh clone
source /opt/ros/humble/setup.bash
cmake -S slam/cmake -B slam/cmake-build -DSLAM_ROS_DISTRO=humble
cmake --build slam/cmake-build --target build_slam
```

## Start SLAM (on the Jetson)

The robot driver enables the motors during startup. Keep the robot in a safe,
clear area and have access to its physical stop before starting.

```bash
source /opt/ros/humble/setup.bash
source slam/install/setup.bash
ros2 run p3at_real run_slam.sh lab        # "lab" = run name; optional launch args after it
```

(`cmake --build slam/cmake-build --target run_slam` does the same, with the default run name.)

Each run gets its own folder, `~/hcr_runs/<date>_<time>_<name>/` (also linked as `~/hcr_runs/latest`).

Start-up order: lidar, then RKO-LIO once clouds are steady (15+ s after the L2 resets), then RTAB-Map
once odometry is steady. **Keep the robot still until RKO-LIO prints
"Odometry map frame initialized".**

## Drive from a Windows/Linux laptop

With SLAM running on the robot, open a terminal on the laptop and run:

```bash
python slam/src/p3at_real/scripts/remote_teleop.py <JETSON_IP>
```

Focus the teleop window to drive: **W/S** forward/back, **A/D** turn,
**Space** stop, **E** e-stop, **U** release e-stop, and **Esc** quit. The sender needs no ROS installation; it uses
Python's standard library and Tk. The robot and laptop must be able to reach
each other over the network (UDP port `9870` by default).

Drive slowly, and finish where you started (or revisit places) so RTAB-Map gets loop closures.

## Motion safety (teleop override, e-stop, collision monitor)

Only `cmd_vel_mux` (started by `robot.launch.py`) publishes `/cmd_vel`. Everything else is an input to it:

```
teleop_receiver / wasd_teleop ─► /cmd_vel_teleop   (priority, cap max_xspeed / max_yawspeed) ─┐
Nav2 ─► collision_monitor      ─► /cmd_vel_nav_safe (cap nav_max_linear 0.3 / nav_max_angular 0.6) ─┼─► cmd_vel_mux ─► /cmd_vel ─► p2os
/estop (std_msgs/Bool)                                                                        ─┘
```

- **Teleop always overrides Nav2.** The goal resumes 0.5 s after you let go, so **Space** stops teleop only.
- **E-stop:** **E** in either teleop window, or
  `ros2 topic pub -w 1 --once /estop std_msgs/msg/Bool "{data: true}"`. This blocks all motion and cancels
  all Nav2 goals. It stays latched until you press **U** or publish `data: false`. The laptop window shows
  when the robot has engaged it. Quitting the teleop does not release it.
- **Collision monitor** (on `/scan`, see `collision_monitor` in `config/nav2_params.yaml`): stops Nav2
  if something is within ~0.3 m of the front bumper, and slows it to 40 % within ~0.75 m.
  The scan cannot see within 0.4 m of the robot centre (`range_min`), so the area right beside the
  robot is blind.
- **Lidar dropout:** the mux drops Nav2 commands (and brakes) if `/scan` is older than 0.6 s.
- `ros2 topic echo /cmd_vel_mux/active` shows who is driving: `teleop`, `nav`, `nav_blocked`, `estop`, `idle`.
- Anything publishing straight to `/cmd_vel` bypasses all of this. Publish to `/cmd_vel_teleop` instead.
- The laptop's copy of `remote_teleop.py` must be updated to get the E/U keys. An old copy still drives.

Press `Ctrl-C` in the SLAM terminal to stop the launch.

## Outputs

In the run folder:

- `map2d.pgm` / `map2d.yaml`: 2D occupancy grid, saved every 15 s
- `rtabmap.db`: keyframes + pose graph (open with `rtabmap-databaseViewer rtabmap.db`)
- `bag/`: raw lidar + IMU, odometries, TF, cmd_vel
- `rko_lio_run_*/`: RKO-LIO trajectory (written on Ctrl-C)
- `console.log`, `ros_log/`

Export the 3D point cloud and poses after Ctrl-C:

```bash
ros2 run p3at_real export_slam.sh ~/hcr_runs/latest   # -> slam/rtabmap_cloud.ply, rtabmap_poses.txt
```
